# 500 篇论文：六策略检索评测

测试集为 [`eval_set_v1.jsonl`](eval_set_v1.jsonl)，生成信息与输入 SHA-256 见 [`eval_set_v1.meta.json`](eval_set_v1.meta.json)。它由 [`make_eval_set.py`](make_eval_set.py) 确定性生成，评测由 [`benchmark.py`](benchmark.py) 执行。评测直接读取已经导入的六个 `papers500_<策略>` Milvus 集合，不重新分块或导入。

## 测试集的两种用途

| 子集 | 数量 | 来源与标签 | 正确解读 |
| --- | ---: | --- | --- |
| `human` | 31 道人工核对题，中文和英文各一次，共 62 条查询；涉及 26 篇不同论文 | 仓库已有 `paper_chunk_v1.jsonl`；保留问题、已知相关 PMCID、原始证据页与答案 | **主检索评测**：衡量 500 篇候选论文中是否排出这一个已知相关论文 |
| `coverage` | 500 条，每篇论文一条；约半数取正文较前位置、半数取较后位置 | 从 `实验2_解析结果/parsed_papers.jsonl` 逐篇截取**字面原文**构造定位查询，相关论文为原文件所属 `doc_id` | **覆盖与索引诊断**：因查询含原文片段，不能充当自然问题的语义检索质量或人工标注 |

两组**分开统计，不合并成一个总分**。同一题可能还有其他相关论文，但数据集只确认一篇。因此脚本报告“已知正例 Hit@1/5/10、MRR@10、nDCG@10”，不称完整 Recall 或 Precision。`human` 的 31 个证据锚点中，28 个在这次解析导出中可逐字找到；其余仍保留原人工标注，供核对解析差异，指标只用 `expected_doc_id`。

`coverage` 的较后位置片段通常超出 400 字符截断基线，部分也超出结构化行入库时的 8192 字节/6000 字符上限。这是该子集要诊断的覆盖差异，不能据此单独判定语义分块优劣。六策略使用完全相同的查询、向量模型、租户/版本过滤、候选块预算和文档去重规则。

自动定位题直接摘录解析正文，可能保留 PDF 双栏串行、断词或页眉噪声；它们是可追溯的索引探针，不是自然语言问答标注。`structured_row` 把论文元数据写进了检索文本，其余策略的元数据仅在字段中，且其中 498 篇的入库文本被截断；这些输入差异会影响对比，报告不能归因于“切块算法”这一单一变量。

## 运行

从项目根目录执行。先离线检查测试集和参数；不会连接 Milvus 或调用向量 API：

```bash
cd /home/ubuntu/RAG-job/LLMHealthyAssistant
python-ai/.venv/bin/python scripts/papers500/benchmark.py --dry-run
```

六策略完整评测（562 条查询 × 6 个集合）：

```bash
python-ai/.venv/bin/python scripts/papers500/benchmark.py
```

会生成查询向量并产生模型 API 用量。若只想先验证 Milvus 搜索链路、**不调用向量 API**：

```bash
python-ai/.venv/bin/python scripts/papers500/benchmark.py \
  --suite human --channels bm25 --strategies baseline --limit 3
```

只运行人工问题：

```bash
python-ai/.venv/bin/python scripts/papers500/benchmark.py --suite human
```

完整评测默认执行 Dense（BGE-M3 + COSINE/HNSW）、Milvus 原生 BM25、Dense+BM25 RRF(k=60) 三个通道。查询向量**每条只生成一次并在六策略中复用**，使用导入集合记录的同一模型和维度；单独计入报告 `query_embedding_ms`，不混入 Milvus 搜索时延。每路取前 100 个**块**候选，再按第一次出现的 `doc_id` 排成最多 10 篇不同论文；RRF 先按块 ID 融合，再按论文去重。这样同一论文的多个块不会占据文档榜多个位置，但固定候选块预算仍可能使高碎片策略得到较少独立论文，报告会记录候选中的独立论文数。

脚本会先核对导入断点的策略、版本、模型、维度、租户和总块数，并在每个集合加载后用 Milvus `count(*)` 再核对实际记录数。集合**逐个加载、检索、卸载**，避免六个实验集合同时常驻内存。检索出错会中止并写入 `status=failed`；不会把查询失败静默算成未命中。正在进行后台索引恢复时，若集合加载失败，应待 Milvus 健康和索引就绪后再运行。

## 报告

默认输出到新的 `data/paper_bench/<时间>/`，可用 `--output-dir` 指定**不存在**的目录。`run.json` 记录完成状态、输入哈希、参数、每策略块数、耗时和按子集/语言/来源/页位置/正文位置分组的指标。`<策略>.jsonl` 逐查询保存期望论文、命中排名、前 10 篇去重结果及搜索时延。即使任务中断，已完成策略也会保留，`run.json` 则标记失败；报告不以失败数据充作完整对比。

评测结果仅说明已知论文的文档级检索排名，不能证明检索到的具体块足以回答人工问题。证据是否支持答案，仍应根据人工题中的 `evidence_anchor` 和原文对命中块进行复核。

## 复现测试集与离线测试

```bash
python-ai/.venv/bin/python scripts/papers500/make_eval_set.py --help
python-ai/.venv/bin/python -m pytest scripts/papers500/tests -q
```

已有 `eval_set_v1.jsonl` 时生成脚本默认拒绝覆盖；确认要重新生成可用 `--force`。重新生成后应检查 `.meta.json` 的输入 SHA-256 与行数，再进行比较。
