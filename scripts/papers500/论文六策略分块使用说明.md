# 500 篇论文六策略分块

脚本：`scripts/papers500/chunk_papers.py`。该脚本生成分块文件；向量导入使用同目录的 `import_vectors.py`，见 [分类目录说明](README.md)。

## 输入与输出

默认读取工作区的 `实验2_解析结果/parsed_papers.jsonl`，知识版本为 `kv_20260928_001`。该文件包含实验 2 导出的 500 篇论文，包括 PDFium 补解析的那一篇。脚本校验篇数、唯一 ID/PMCID、版本、非空正文和内容哈希，再按 PMCID 排序逐篇分块；不同论文不会混入同一个块。

输入是已导出的文件，不需要启动 PostgreSQL 或 Milvus。脚本会加载项目根目录 `.env`。只有 `semantic_split` 调用项目的 SiliconFlow embedding 适配器，用句段向量判断边界；会产生 API 用量，也可能使用项目已有缓存。输出不包含检索向量，不写入 PostgreSQL/Milvus，不发布知识版本。

默认输出目录：`LLMHealthyAssistant/data/paper_chunks/<本次时间>/`。也可以通过 `--output-dir` 指定一个尚不存在的目录，避免覆盖旧结果。

每种策略输出：

- `<策略名>.jsonl`：块正文、块 ID、来源文档 ID、PMCID、知识版本、论文元数据、请求策略、实际策略和回退原因。
- `<策略名>_papers.jsonl`：逐篇块数和回退情况。
- `summary.json`：输入文件 SHA-256、运行参数、完成状态、论文数、块数、平均/最小/最大长度、超长块数、回退论文数、embedding 批次调用数和耗时。
- `run.log`：每处理 10 篇记录一次进度。

长度均为 Python 字符数，不是 token 数；重叠文本会重复计入输出字符总数。脚本不生成 Recall/MRR 等检索评测结果。

## 六种策略与原项目的对应关系

| 策略 | 处理方式 | 长度与重叠 |
| --- | --- | --- |
| `baseline` | 默认每篇只保留正文前 400 字符，沿用 `app/eval/chunk_bench.py` 的截断基线 | 一个块；可用 `--baseline-mode full` 改为全文一个块 |
| `fixed_length` | 直接调用 `chunk_fixed_length` | 默认 400 字符，无重叠 |
| `fixed_symbol` | 直接调用 `chunk_fixed_symbol`，按原项目的换行和中文标点分割、合并 | 400 为目标值，无重叠；无可用分隔符的长段可能超限 |
| `semantic_window` | 直接调用 `chunk_sliding_window` | 默认 400 字符、64 字符重叠；属于句段窗口，不调用模型 |
| `semantic_split` | 直接调用 `chunk_semantic_by_similarity` | 默认 400 字符、64 字符重叠，相似度阈值 0.55，最小填充比例 0.35；原始长句段可能超限 |
| `structured_row` | 按实验 3 论文补充实验的定义，一篇论文作为一个结构化记录：PMCID、标题、期刊、年份、主题、DOI、许可加完整正文 | 一个块，不受 400 字符限制 |

其中四种文本切分函数来自 `app/retrieval/chunk_strategies/`，脚本没有重写其算法。`structured_row` 是论文元数据加全文，并非自动识别论文表格或章节。其元数据写进 `text`，其他策略的元数据单独保存在 `metadata`，后续若按标题比较检索效果，需考虑这种输入差异。

旧实验 3 的论文补充记录采用“全文一个块”的 baseline；想对照该记录应显式使用 `--baseline-mode full`。默认截断基线则与仓库现有 `chunk_bench.py` 一致。

超长块保留在实验产物中，`summary.json` 的 `over_chunk_size` 会如实统计；这些文件不是可以直接批量写入现有 Milvus schema 的数据，尤其全文块需要在后续入库阶段处理模型和字段长度限制。

## 执行全部 500 篇、全部六种策略

在服务器终端运行：

```bash
cd /home/ubuntu/RAG-job/LLMHealthyAssistant
python-ai/.venv/bin/python scripts/papers500/chunk_papers.py
```

默认参数：500 篇、`kv_20260928_001`、400 字符、64 字符重叠、六种策略。必须在 `.env` 配置有效的 `SILICONFLOW_API_KEY`；embedding 模型和维度沿用现有 `EMBEDDING_MODEL` / `EMBEDDING_DIM`。

全部六种策略按顺序执行。句段向量默认每批 16 条请求；对 500 篇全文做语义分块可能耗时较长，API 用量随句段数变化。调用批次统计包含缓存命中的适配器调用，不等同于实际 HTTP 请求数。

对照旧论文实验，并指定输出目录：

```bash
python-ai/.venv/bin/python scripts/papers500/chunk_papers.py \
  --baseline-mode full \
  --chunk-size 400 --overlap 64 \
  --output-dir data/paper_chunks/papers500_full_baseline
```

## 先用少量论文确认配置

这是执行同一个正式脚本的限量选项，不是测试脚本；以下命令本次也未执行：

```bash
python-ai/.venv/bin/python scripts/papers500/chunk_papers.py \
  --limit 3 \
  --output-dir data/paper_chunks/preview3
```

仍然先校验输入有 500 篇，再取 PMCID 排序后的前 3 篇。该命令包含语义策略，会调用 embedding API。

## 先运行不调用 API 的五种策略

```bash
python-ai/.venv/bin/python scripts/papers500/chunk_papers.py \
  --strategies baseline fixed_length fixed_symbol semantic_window structured_row \
  --output-dir data/paper_chunks/papers500_local
```

之后单独运行语义切分：

```bash
python-ai/.venv/bin/python scripts/papers500/chunk_papers.py \
  --strategies semantic_split \
  --embedding-batch-size 16 \
  --output-dir data/paper_chunks/papers500_semantic
```

## API 异常与回退

原项目的语义切分函数会在 embedding 异常时自动返回窗口切分。为避免误把这种结果当作真正语义分块，脚本默认 `--semantic-fallback error`：记录失败状态并终止，保留之前已完成的策略文件。

若希望遇到 API 错误仍继续处理，可显式选择：

```bash
python-ai/.venv/bin/python scripts/papers500/chunk_papers.py \
  --strategies semantic_split \
  --semantic-fallback window \
  --output-dir data/paper_chunks/papers500_semantic_with_fallback
```

回退块会标记 `strategy=semantic_split`、`actual_strategy=semantic_window`，并保存 `fallback_reason`，汇总中记录回退篇数。原实现发现全文无法切出多个句段时也会改用窗口策略；这是输入结构导致的回退，在两种模式下都会记录为 `insufficient_sentence_segments`。

出现错误或手动中断时，检查 `summary.json` 的 `status`。未完成的策略正文文件保留为 `.jsonl.partial`，不能视为完整结果；逐篇统计也可能只写入一部分。脚本不自动断点续跑，可只选择未完成策略，使用新输出目录重新执行。

## 其他参数

```bash
python-ai/.venv/bin/python scripts/papers500/chunk_papers.py --help
```

`--input` 可指定另一份同格式导出文件；`--version`、`--expected-papers` 必须与输入一致。输入必须保留实验 2 的 `content_hash`。比较不同块长时使用不同输出目录，例如 `--chunk-size 800 --overlap 128`；不要通过修改原项目脚本中的常量来切换参数。
